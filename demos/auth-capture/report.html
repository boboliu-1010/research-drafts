发现的问题：sync 后 SDK 账本没有同步

链上已经 capture 0.006、void 0.004，SDK 存储仍显示可扣 0.01、可退 0。再调用 lifecycle.refund 时返回 invalid_auth_capture_evm_unexpected_payment_state，没有广播退款交易。

core 向 facilitator 发送了补齐后的 capture payload，却将原 collect payload 传给 afterSettle。auth-capture 的回调看不到 type=capture，因而漏更新存储。SDK 源码保持原样，本地无链复现也得到相同结果。

该笔退款由 operator 直接调用 Escrow 完成，不能算 SDK 退款流程通过。查看恢复退款回执。接入前需要修复回调的数据传递并补回归测试。

源码与工具链

官方合约测试 112 项通过，其中 94 项 fuzz 测试共 24,064 轮；排除了上游 Base 主网 fork 集成测试。合约用 Solidity 0.8.28 重新编译，与链上代码比较时归一化了构造时写入的 immutable。Escrow 和 TokenStore 模板完整 runtime 匹配；三个 Collector 需要额外去掉末尾的 CBOR 编译元数据。

Foundry v1.8.5 有一个 Permit2/ERC-6492 用例失败，官方 CI 的 v1.3.6 全部通过。SDK 472 项单测通过；HTTP 实测发现 sync 账本更新遗漏，详情见上方公开链记录。
